## 1. conftest

`conftest.py` 是 pytest 的**特殊配置文件**，用來集中管理測試的共用設定與資源。

- **不需要 import**，pytest 自動發現並載入
- 位置決定影響範圍（同目錄及子目錄）

```
project/
├── conftest.py          ← 全域，所有測試都能用
├── tests/
│   ├── conftest.py      ← 只影響 tests/ 目錄
│   └── api/
│       ├── conftest.py  ← 只影響 tests/api/
│       └── test_api.py
```

## 2. Fixture Scope

| scope | 建立時機 | 銷毀時機 | 適合場景 |
|---|---|---|---|
| `function` | 每個 test 前 | 每個 test 後 | DB session、Redis client |
| `class` | 每個 class 前 | 每個 class 後 | — |
| `module` | 每個檔案前 | 每個檔案後 | — |
| `session` | 整個測試開始 | 整個測試結束 | engine、connection pool |

```
pytest 執行
│
├── session 開始
│   └── engine fixture 建立一次（scope="session"）
│
├── test_user.py
│   ├── function 開始 → db_session 建立 → 執行 → rollback/清除
│   └── function 開始 → db_session 建立 → 執行 → rollback/清除
│
└── session 結束 → engine drop tables & dispose
```

## 3. engine.begin()

`engine.begin()` = 取出連線 + 自動開 transaction + 自動 commit/rollback

```python
async with engine.begin() as conn:
    await conn.run_sync(Base.metadata.create_all)
# 成功 → 自動 COMMIT
# 例外 → 自動 ROLLBACK
```

對比：

| | `engine.connect()` | `engine.begin()` |
|---|---|---|
| 自動 transaction | ❌ | ✅ |
| 自動 commit | ❌ | ✅ |
| 自動 rollback | ❌ | ✅ |
| 適合場景 | 讀取、手動控制 | 寫入、DDL（create/drop table） |

## 4. Session Scope 卡住

### 問題原因

`asyncpg` 的連線**綁定在建立它的 event loop** 上：

```
engine（scope=session）用 event loop A 建立 connection pool
db_session（scope=function）跑在 event loop B
→ 用 loop B 操作 loop A 的連線 → 卡住
```

### 解決方法

**方法一：強制共用同一個 loop（推薦）**

```python
# conftest.py
import asyncio, pytest

@pytest.fixture(scope="session")
def event_loop():
    loop = asyncio.new_event_loop()
    yield loop
    loop.close()
```

```ini
# pyproject.toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
asyncio_default_fixture_loop_scope = "session"
```

**方法二：engine 改成 function scope（最簡單，但較慢）**

```python
@pytest_asyncio.fixture(scope="function")
async def engine():
    ...
```

## 5. 完整 conftest.py 設定

```python
# tests/conftest.py
import pytest_asyncio
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from redis.asyncio import ConnectionPool, Redis
from sqlalchemy import delete
from app.models import User, Task

TEST_SQLALCHEMY_DATABASE_URL = "postgresql+asyncpg://user:pass@localhost/test_db"
TEST_REDIS_DATABASE_URL = "redis://localhost:6379/1"

@pytest_asyncio.fixture(scope="session")
async def engine():
    engine = create_async_engine(TEST_SQLALCHEMY_DATABASE_URL)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    yield engine
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all)
    await engine.dispose()

@pytest_asyncio.fixture(scope="session")
async def init_redis_pool():
    pool = ConnectionPool.from_url(
        TEST_REDIS_DATABASE_URL, max_connections=10, decode_responses=True
    )
    yield pool

@pytest_asyncio.fixture(scope="function")
async def get_db(engine):
    AsyncSessionFactory = async_sessionmaker(engine, expire_on_commit=False)
    async with AsyncSessionFactory() as session:
        try:
            yield session
        finally:
            await session.execute(delete(Task))  # Task 有 FK，先刪
            await session.execute(delete(User))
            await session.commit()

@pytest_asyncio.fixture(scope="function")
async def get_redis(init_redis_pool):
    async with Redis(connection_pool=init_redis_pool) as redis:
        yield redis
        await redis.flushdb()

@pytest_asyncio.fixture(scope="function")
async def client(get_db, get_redis):
    app.dependency_overrides[app_get_db] = lambda: get_db
    app.dependency_overrides[app_get_redis] = lambda: get_redis
    async with AsyncClient(
        transport=ASGITransport(app=app),
        base_url="http://test",
        follow_redirects=True   # 避免 307 redirect 問題
    ) as ac:
        yield ac
    app.dependency_overrides.clear()
```

## 6. dependency_overrides

FastAPI **內建**的功能，專門用來在測試時替換依賴注入。

```python
# 正式環境
async def get_db():
    async with SessionLocal() as session:
        yield session

# 測試時替換
app.dependency_overrides[get_db] = override_get_db
```

本質是一個 **dict**，key 是原本的函式，value 是替換的函式：

```python
app.dependency_overrides[get_db] = override_get_db  # 新增
del app.dependency_overrides[get_db]                 # 刪除單一
app.dependency_overrides.clear()                     # 清除全部（測試結束後必做）
```

> ⚠️ key 必須是函式本身，不能是字串

FastAPI 處理請求流程：
```
Depends(get_db)
    └── 檢查 dependency_overrides 有沒有 get_db
            ├── 有 → 用替換的函式
            └── 沒有 → 用原本的函式
```

---

## 7. 為什麼要用 lambda

`dependency_overrides` 期望的是一個 **callable（可被呼叫的函式）**。

```python
# ✅ 直接傳函式
app.dependency_overrides[get_db] = override_get_db

# ✅ lambda 把已有的變數包成函式
app.dependency_overrides[get_db] = lambda: get_db    # 回傳 db session 物件

# ❌ 錯誤：回傳的是函式本身而非值
app.dependency_overrides[get_db] = lambda: get_db_func
```

## 8. @pytest.mark.asyncio

pytest 本身只認識同步函式，`@pytest.mark.asyncio` 告訴 pytest 這個 test 是 async 的。

| 寫法 | 說明 |
|---|---|
| 每個 method 加 `@pytest.mark.asyncio` | 最明確 |
| 整個 class 加 `@pytest.mark.asyncio` | 推薦 |
| `asyncio_mode = "auto"` | 最省事，完全不用加 |

```ini
# pyproject.toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
```

## 9. Class vs Function 風格

推薦用 **class 按 endpoint 分組**：

```python
@pytest.mark.asyncio
class TestRegister:
    async def test_success(self, client): ...
    async def test_duplicate(self, client): ...

@pytest.mark.asyncio
class TestLogin:
    async def test_success(self, client): ...
    async def test_wrong_password(self, client): ...
```

pytest 輸出：
```
TestRegister::test_success          PASSED
TestRegister::test_duplicate        PASSED
TestLogin::test_success             PASSED
TestLogin::test_wrong_password      FAILED  ← 一眼看出哪個 endpoint 出問題
```

檔案結構建議：
```
tests/api/
├── test_auth.py   ← TestRegister, TestLogin, TestRefresh
└── test_task.py   ← TestGetTasks, TestCreateTask, TestUpdateTask, TestDeleteTask
```

## 10. Setup Fixture (autouse)

每個 test 執行前自動先做某件事：

```python
class TestLogin:
    @pytest_asyncio.fixture(autouse=True)
    async def setup(self, client: AsyncClient):
        """每個 test 前自動執行"""
        await client.post("/auth/register", json={
            "username": "alice",
            "password": "password123"
        })

    async def test_login_success(self, client):
        # 不需要再 register，setup 已處理
        ...
```

| | 執行 fixture？ |
|---|---|
| 參數有加 fixture | ✅ 執行 |
| 參數沒有加 fixture | ❌ 不執行 |
| `autouse=True` | ✅ 永遠執行 |

## 11. registered_user fixture

用 dataclass 讓 type hint 更清楚：

```python
from dataclasses import dataclass

@dataclass
class RegisteredUser:
    username: str
    password: str
    access_token: str
    refresh_token: str | None

@pytest_asyncio.fixture(scope="function")
async def registered_user(client: AsyncClient) -> RegisteredUser:
    payload = {"username": "test_user", "password": "test_password"}
    response = await client.post("/auth/register", json=payload)

    if response.status_code != 201:
        raise RuntimeError(f"註冊失敗，無法建立測試資料: {response.json()}")

    data = response.json()
    return RegisteredUser(
        username=payload["username"],
        password=payload["password"],
        access_token=data["access_token"],
        refresh_token=response.cookies.get("refresh_token")
    )
```

使用：
```python
async def test_login(self, client, registered_user: RegisteredUser):
    response = await client.post("/auth/login", json={
        "username": registered_user.username,  # 用 . 取值，IDE 有自動補全
        "password": registered_user.password
    })
```

## 12. Fixture 裡不要放 assert

```python
# ❌ 不好：fixture 做了測試的事
@pytest_asyncio.fixture
async def registered_user(client):
    response = await client.post("/auth/register", json={...})
    assert response.status_code == 201  # 應該移除

# ✅ 好：用例外處理
@pytest_asyncio.fixture
async def registered_user(client):
    response = await client.post("/auth/register", json={...})
    if response.status_code != 201:
        raise RuntimeError(f"無法建立測試資料: {response.json()}")
    ...
```

原因：
- fixture 的職責是**準備資料**，不是驗證行為
- fixture 裡的 assert 失敗，錯誤會指向 fixture 而非某個測試，難以定位
- fixture 失敗會讓所有依賴它的測試都跳過

## 13. AsyncClient

測試時 FastAPI app **沒有真正啟動伺服器**，`AsyncClient` + `ASGITransport` 讓請求直接在記憶體內處理：

```
一般情況：測試 → 真實網路 → http://localhost:8000 → FastAPI
測試時：  測試 → AsyncClient → ASGITransport → FastAPI（記憶體內，不需啟動伺服器）
```

```python
async with AsyncClient(
    transport=ASGITransport(app=app),  # 指定用 FastAPI app 處理請求
    base_url="http://test",            # 假的 base URL，不會真的連線
    follow_redirects=True              # 避免 307 redirect 問題
) as ac:
    yield ac
```

## 14. Cookie & Header 寫法

| 角色 | 動作 | 寫法 |
|---|---|---|
| FastAPI（Server） | 設定 cookie 給瀏覽器 | `res.set_cookie(key, value, httponly=True)` |
| AsyncClient（測試） | 模擬帶 cookie | `client.cookies.set("refresh_token", token)` |
| AsyncClient（測試） | 模擬帶 header | `headers={"Authorization": f"Bearer {token}"}` |
| AsyncClient（測試） | 刪除 cookie | `client.cookies.delete("refresh_token")` |
| 取 response 的 cookie | 取得 server 新設定的值 | `res.cookies.get("refresh_token")` |

Refresh token 測試範例：
```python
async def test_refresh_success(self, client, registered_user):
    old_token = registered_user.refresh_token
    client.cookies.set("refresh_token", old_token)

    res = await client.post("/auth/refresh")

    assert res.status_code == 200
    assert "access_token" in res.json()

    new_token = res.cookies.get("refresh_token")  # server set_cookie 的新值
    assert new_token is not None
    assert new_token != old_token  # 確認有更新
```

## 15. httpx 的用途

`httpx` 是**通用的 HTTP client**，不只用在測試：

| | requests | httpx |
|---|---|---|
| 同步 | ✅ | ✅ |
| 非同步 | ❌ | ✅ |
| 測試 FastAPI | ❌ | ✅ |
| 實務打外部 API | ✅ | ✅ |

在 FastAPI async 專案裡，`httpx` 通常直接取代 `requests`：

```python
# 在 FastAPI 裡打外部 API
@router.get("/github/{username}")
async def get_github_user(username: str):
    async with httpx.AsyncClient() as client:
        res = await client.get(f"https://api.github.com/users/{username}")
        return res.json()
```

## 16. 常見錯誤排查

### 307 Temporary Redirect

```
E   assert 307 == 200
```

原因：URL 結尾的 `/` 不符合 router 定義

```python
# router prefix="/tasks", endpoint="/"  → 打 /tasks/
# router prefix="/tasks", endpoint=""   → 打 /tasks

# 一勞永逸的解法：conftest 加 follow_redirects=True
async with AsyncClient(..., follow_redirects=True) as ac:
    yield ac
```

---

### 422 Unprocessable Entity（測試 not found）

```
E   assert 422 == 404
```

原因：`task_id` 型別不符，FastAPI 在進 function 前就驗證失敗

```python
# task_id 是 int  → 用數字
await client.patch("/tasks/99999", ...)

# task_id 是 UUID → 用 uuid4()
import uuid
await client.patch(f"/tasks/{uuid.uuid4()}", ...)

# task_id 是 str  → 任意字串都行
await client.patch("/tasks/nonexistent_id", ...)
```
